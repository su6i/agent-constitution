# قوانین گیت

## قانون طلایی

هر تسک = یک کامیت = یک شاخه (Branch) ویژگی.

## فرمت پیام کامیت

`[نوع]: [توضیح کوتاه]`
انواع: feat, fix, test, refactor, docs, chore.

## قبل از کامیت

۱. اجرای روف (`ruff`) برای اصلاح استایل.
۲. اجرای تست‌ها (`pytest`).
۳. بررسی اسرار و کلیدهای امنیتی.

## ممنوع

CRITICAL: NEVER make any code modifications or git commits while on the 'main' branch. Your FIRST action for any task MUST BE: `git checkout -b <branch_name>`. The system will block any direct commits to main.

- پیام‌های نامفهوم مثل "update" یا "changes".

## دستورهای ممنوعِ درختِ کاری (غیرقابلِ مذاکره)

<!-- digest:start -->
دو دستور کاملاً ممنوع‌اند، چون هر دو کارِ کامیت‌نشده را **بدون هیچ راهِ بازگشتی**
دور می‌ریزند (حکمِ مالک ۲۰۲۶-۰۸-۱۰):

- **`git checkout -- <file>`** — نسخه‌ی درختِ کاریِ فایل را به آخرین کامیت
  برمی‌گرداند و **هیچ‌جا چیزی ذخیره نمی‌کند**. ویرایش‌های دورریخته رفته‌اند؛ نه
  ref ی هست، نه ورودیِ reflog، نه راهِ بازگشتی.
- **`git stash`** — به‌نظر می‌رسد کار را ذخیره می‌کند، ولی در عمل آن را **پنهان**
  می‌کند: stash به هیچ شکلی که گیت تضمینش کند به برنچِ سازنده‌اش گره نخورده، پس
  به‌محضِ حذفِ آن برنچ، stash به یک ارجاعِ یتیم تبدیل می‌شود که هیچ‌کس فکرش را
  نمی‌کند دنبالش بگردد. حادثه‌ی واقعی، همان سشنِ صدورِ این حکم: دو stash
  (`multi-agent_financial_markets_analyser` و `youtube_toolkit`) روی برنچِ
  `feature/session-start-rule` ساخته شد؛ برنچ حذف شد و کارِ مالک عملاً گم شد تا
  وقتی که خودِ مالک شخصاً دستورِ `stash pop` داد — که آن هم به تعارضِ merge خورد.

**جایگزینِ مجاز:** تنها راهِ امنِ حفظِ کارِ کامیت‌نشده، **کامیت روی برنچِ خودش**
است. اگر تغییر مالِ خودِ ایجنت نیست و تکلیفش روشن نیست، **بایست و از مالک بپرس** —
هرگز دورش نریز، هرگز stash ش نکن (هم‌راستا با «بپرس، دورِ فایلِ محافظت‌شده نزن»).

**صراحتاً مشمولِ این ممنوعیت نیست:** `git restore --staged <file>` فقط فایل را از
حالتِ stage خارج می‌کند — به درختِ کاری دست نمی‌زند، پس چیزی دور ریخته نمی‌شود.
یکی‌گرفتنِ این دو باعث می‌شود ایجنت از هر دو بترسد؛ این‌ها یک عملیات نیستند.
